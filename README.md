# SignBridge 2.0

مشروع تخرج للتواصل والتعلم حول لغة الإشارة المصرية. الواجهة React + TypeScript، والخادم FastAPI، والبيانات SQLite.

## ما يعمل الآن

- نص عربي إلى فيديوهات إشارات مصرية حقيقية من قاموس محلي فيه **32 كلمة وعبارة**. البحث يفهم بعض البدائل الإملائية والعامية ويختار أطول عبارة مطابقة.
- تشغيل الفيديوهات بالتتابع، السابق والتالي، وتغيير السرعة. أي كلمة غير متاحة تظهر بوضوح، ولا نخترع إشارة بديلة.
- **6 دروس فيديو**، اختبارات اختيار من متعدد، تصحيح على الخادم وحفظ أفضل تقدم، وحفظ الإشارات والدروس. توجد أيضاً 4 قوائم مفردات نصية قديمة، ومكتوب عليها أنها نصية.
- حسابات وجلسات HttpOnly، تسجيل خروج يلغي الجلسة، تأكيد بريد واستعادة كلمة مرور بروابط تستخدم مرة واحدة.
- صندوق بريد تجريبي Mailpit لعرض رسائل التأكيد والاستعادة **بدون أي حساب بريد أو كلمة مرور SMTP حقيقية**.
- روابط للصفحات، الرجوع والتقدم في المتصفح، فتح الدرس برابط، وتحديث الصفحة بدون الرجوع للرئيسية.
- محادثة مكتوبة على جهاز واحد، عبارات محفوظة، ملاحظات مرتبطة بطلب العرض، ولوحة مسؤول لقراءة الملاحظات.
- تصدير البيانات، وتنزيل **كل** سجل الطلبات مع النتائج والكلمات الناقصة، وحذف الحساب وبياناته النشطة.

## حدود مهمة قبل العرض

هذا **قاموس كلمات وعبارات منفصلة، وليس ترجمة لقواعد جمل كاملة**. لا يغير ترتيب الجملة ولا يفهم السياق. الكلمات غير الموجودة لا تتحول إلى فيديو. تسميات المصدر ومطابقتها بالعربية لم يراجعها خبير مستقل.

**التعرف بالكاميرا، من إشارة إلى نص، غير متاح.** لا يوجد موديل تعرف تم تدريبه وتقييمه هنا. الكاميرا للمعاينة المحلية فقط. واجهة التوسعة موضحة في `backend/translation.py` و`docs/TRANSLATION.md`. لا تستخدم المشروع للطب أو القانون أو الطوارئ بدلاً من مترجم مؤهل.

## أسرع تشغيل لعرض المناقشة: Docker

يلزم Docker Desktop أو Docker Engine مع Compose. من المجلد الذي فيه هذا الملف:

```bash
docker compose up --build
```

بعد اكتمال البناء:

- التطبيق: http://localhost:8000
- صندوق البريد التجريبي: http://localhost:8025
- توثيق API: http://localhost:8000/docs

أنشئ حساباً بأي عنوان تجريبي، مثل `student@example.test`. افتح Mailpit وستجد رسالة التأكيد. افتح رابطها واضغط تأكيد. جرب أيضاً "نسيت كلمة المرور" وستصل رسالة الاستعادة لنفس الصندوق. **الرسائل لا تصل إلى الإنترنت أو إلى صندوق بريد حقيقي.** كل العناوين تصل إلى Mailpit المحلي، فلا تضع بيانات شخصية حقيقية أثناء العرض.

جرب في صفحة الترجمة: `صباح الخير عامل إيه`، ثم `صباح الخير موز` لتوضيح الكلمات غير المتاحة. افتح مركز التعلم لعرض القاموس بالكامل والاختبارات.

إيقاف العرض:

```bash
docker compose down
```

بيانات التطبيق تبقى في volume اسمه `signbridge_data`. لحذف بيانات العرض نهائياً استخدم `docker compose down -v`. رسائل Mailpit التجريبية مؤقتة وتختفي مع إزالة حاويته. لا تعرض منافذ Mailpit أو وضع التطوير على الإنترنت.

## تشغيل للتعديل، بدون Docker

المتطلبات: Node.js 22.22.2 أو أحدث ضمن سلسلة 22، وPython 3.10+.

```bash
npm run setup
npm run dev
```

التطبيق على http://localhost:5173 والخادم على http://localhost:8000 . التثبيت الأول يحتاج إنترنت لتحميل الحزم. الفيديوهات والخطوط مرفقة محلياً ولا تحتاج خدمة خارجية بعد التثبيت.

بدون SMTP، يحفظ وضع التطوير رسائل البريد كملفات `.eml` في `backend/data/dev-outbox/`. افتح الملف في برنامج بريد وافتح الرابط منه، أو شغل Mailpit ثم عدل `backend/.env`:

```dotenv
SMTP_HOST=127.0.0.1
SMTP_PORT=1025
SMTP_STARTTLS=0
SMTP_DEMO=1
MAIL_FROM=SignBridge Demo <no-reply@signbridge.test>
APP_URL=http://localhost:5173
```

لتشغيل Mailpit وحده من المشروع: `docker compose up mailpit` لا ينشر منفذ SMTP للمضيف افتراضياً. للتشغيل المحلي بدون حاوية التطبيق، استخدم أمر Mailpit الرسمي التالي بدلاً منه:

```bash
docker run --rm -p 127.0.0.1:8025:8025 -p 127.0.0.1:1025:1025 axllent/mailpit:v1.33.0
```

أعد تشغيل خادم Python بعد تعديل `.env`. لا توجد كلمات مرور أو مفاتيح بريد جاهزة أو مخفية في المشروع.

## الأوامر والاختبارات

```bash
npm test                     # اختبارات Python
npm run test:web             # اختبارات الواجهة
npm run lint                 # ESLint
npm run build                # TypeScript + Vite
npm run test:e2e             # بناء واختبارات متصفح مع API حقيقي
npm start                    # بناء ثم تشغيل الواجهة وAPI على :8000
```

قبل أول اختبار متصفح: `cd frontend` ثم `npx playwright install chromium` ثم ارجع إلى جذر المشروع. يستخدم اختبار المتصفح Python الموجود على المسار. لو ثبتت عن طريق setup، فعل `.venv` أولاً. يمكن أيضاً ضبط متغير `PYTHON` لمساره.

الاختبارات تشمل عزل الحسابات، انتهاء وإلغاء الجلسات، CSRF، تأكيد البريد والاستعادة والاستخدام الواحد للرابط، القفل بعد فشل الدخول، حدود الطلبات الدائمة، القاموس والوسائط، الاختبارات التعليمية، التصدير والتقسيم إلى صفحات، حذف الحساب، وترقية القاعدة والتشغيل المتزامن. سيناريو المتصفح يشمل تشغيل الفيديو فعلياً، الروابط وتحديث الصفحة، الاختبار التعليمي والحفظ، وشاشة الموبايل.

لاختبار SMTP الحقيقي مع Mailpit، ثبت Mailpit من موقعه الرسمي ثم مرر مسار الملف التنفيذي في `MAILPIT_BIN` عند تشغيل Playwright. هذا يشغل SMTP وصندوقه أثناء الاختبارات، ويتحقق من وصول الرسالتين وإتمام روابطهما. بدون هذا المتغير تستخدم الاختبارات ملفات EML المحلية.

## النشر الحقيقي، منفصل عن عرض المناقشة

استخدم خادماً بقرص دائم وHTTPS. **لا تنشر ملف Compose التجريبي على الإنترنت.** ملف `compose.production.yaml` مستقل، لا تضفه كطبقة فوق ملف العرض:

```bash
docker compose -f compose.production.yaml up --build -d
```

يلزم ضبط `APP_URL` إلى أصل HTTPS الصحيح، و`SMTP_HOST` و`MAIL_FROM` وأي بيانات دخول يطلبها مزود البريد، عبر متغيرات البيئة الخاصة بالخادم. الإنتاج يستخدم STARTTLS ويفحص شهادة الخادم، ويمنع SMTP غير المشفر. لا تطلب المنصة بريدك الحقيقي لتشغيل العرض التجريبي.

اجعل reverse proxy يخدم الواجهة و`/api` و`/media` من **نفس الأصل**. لا تستخدم `VITE_API_URL` لموقع مختلف. في حالة تفعيل `TRUST_PROXY` يجب أن يستبدل الوكيل قيمة X-Forwarded-For بقيمة موثوقة، وألا يكون التطبيق مكشوفاً مباشرة.

SQLite مناسبة لنسخة واحدة بقرص محلي دائم، وليست لعدة نسخ مستقلة أو تخزين شبكي. حدود الطلبات محفوظة في القاعدة وتشاركها العمليات التي تستخدم الملف نفسه. النشر بإنتاج SQLite على Vercel أو تخزين مؤقت مرفوض لحماية البيانات. أزيل وصف Vercel القديم غير المناسب. ضع سياسة نسخ احتياطي ومدة احتفاظ ووسيلة تواصل حقيقية قبل أي نشر عام.

## المسؤول

لم يعد `ADMIN_EMAILS` يمنح الصلاحية عند التسجيل. أنشئ الحساب وأكد بريده، ثم على الخادم، من مجلد backend:

```bash
python grant_admin.py student@example.test
```

لا يمنح الأمر الصلاحية لحساب غير مؤكد. في Docker يمكن تشغيل الأمر داخل حاوية التطبيق. تظهر الملاحظات للمسؤول في الإعدادات. لا تشارك حساب المسؤول مع مستخدمي التطبيق.

## الملفات والحقوق

- `backend/signs.json`: كل فيديو ومصدره وترخيصه وبصمته الأصلية وبصمة النسخة المرفقة.
- `backend/media/`: 32 فيديو مرخصاً، بحجم إجمالي يقارب 4 MB.
- `docs/TRANSLATION.md`: طريقة القاموس وحدودها وتوسعة التعرف مستقبلاً.
- `THIRD_PARTY_NOTICES.md`: نسب المواد وتراخيصها. مصدر الفيديو: https://data.mendeley.com/datasets/39tbt2jd7r/1
- `LICENSE`: يحفظ حقوق أصحاب كود المشروع، ولا يختار ترخيص نشر مفتوح باسمهم. اختر الترخيص المناسب قبل نشر الكود. الفيديوهات نفسها CC BY 4.0.
- `frontend/.env.example` و`backend/.env.example`: الإعدادات.
- `Dockerfile` وملفا Compose و`.github/workflows/ci.yml`: البناء والفحوص.
- صفحة الخصوصية وحدود الخدمة على `/privacy`، ومتاحة قبل تسجيل الدخول.

الحزم مثبّتة بالإصدارات في `backend/requirements.lock` و`frontend/package-lock.json`. لا يتضمن الأرشيف قاعدة بيانات مستخدمين أو أسراراً أو node_modules أو بيئة Python. يتضمن كود المصدر والوسائط والاختبارات، ونسخة الواجهة المبنية في `frontend/dist/` للتشغيل المباشر مع الخادم.
